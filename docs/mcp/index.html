MCP server

Agent-facing tools over the measurement corpus. Every tool delegates to the same py-core builders as the REST API, so an agent search and a UI search cannot drift.

Run it

just dev-mcp
# or
.venv/bin/python -m omat_mcp.server

The entry point speaks stdio. The Python SDK also supports streamable HTTP for a future ALB deployment; no public MCP endpoint is deployed yet.

Tools read OpenSearch directly, so start the stack and load the index before connecting a client: 

just up
just index data/final_data.csv

Connect a client

Point any stdio MCP client at the workspace virtualenv. Replace the command path with your checkout: 

{
  "mcpServers": {
    "omat-se": {
      "command": "/absolute/path/to/Omat-se/.venv/bin/python",
      "args": ["-m", "omat_mcp.server"],
      "env": {
        "OMAT_OPENSEARCH_URL": "http://localhost:9200"
      }
    }
  }
}

The literature tools additionally need OMAT_VALENCY_BEARER_TOKEN. Without it they return {"available": false} instead of failing.

Tools

search_records

search

search_records(query="", elements=None, property_slug=None, min_value=None, max_value=None, journal=None, applications=None, limit=10)

Search measurement records by free text, composition, property, journal, or application. Natural-language questions are mapped to application and property boosts by py-core before the query runs. Filters are OR within a field and AND across fields.

Returns: a list of records with record_id, article_pii, doi, composition, property, elements, journal, year, applications, and title. limit is clamped to 1–50.

Example: search_records(query="TiAlN coating", elements=["Ti", "Al"], limit=5)

get_paper

papers

get_paper(doi_or_pii)

Return every measurement row for one paper. Values starting with 10. are treated as a DOI (lowercased); anything else is treated as an article PII (uppercased).

Returns: {doi, article_pii, title, record_count, records}, or {"error": "paper not found"}.

Example: get_paper("10.1016/j.matlet.2020.129009")

facet_counts

facets

facet_counts(field="property", query="", elements=None, journal=None, applications=None)

Count records per facet value under the same filters as search_records. Fields: property, elements, journal, application, year_histogram, and property_stats.

Returns: [{value, count}] for bucket fields; {count, min, max, avg, sum} for property_stats.

Example: facet_counts(field="application", query="concrete")

suggest

autocomplete

suggest(q, limit=8)

Prefix autocomplete over composition formulas, element symbols, property slugs, and journal slugs. Use it to resolve user input into exact facet values before searching.

Returns: {query, formulas, elements, properties, journals}. limit is clamped to 1–20.

Example: suggest("ti")

props_scatter

aggregate

props_scatter(property_a, property_b, property_c, threshold_a=None, threshold_b=None, threshold_c=None, elements=None, journal=None, applications=None)

Three-property scatter for materials measured for all three properties. Points outside the 1st/99th percentile on any axis are dropped. When all three thresholds are supplied, points satisfying x >= threshold_a and y >= threshold_b and z >= threshold_c are flagged.

Returns: {property_a, property_b, property_c, thresholds, points, bounds, counts}, where each point is [x, y, z, highlighted].

Example: props_scatter("glass_transition_temperature", "activation_energy", "crystallization_temperature", 600, 2, 800)

gsc_chart

aggregate

gsc_chart(property_a, property_b, elements=None, journal=None, applications=None)

Two-property composition-family hulls. Materials measured for both properties are grouped by element set; each family carries its points and a smoothed convex hull.

Returns: {property_a, property_b, families, total_points}; each family has family, count, points, and hull.

Example: gsc_chart("youngs_modulus", "hardness")

search_literature

external

search_literature(query, limit=8)

Semantic search over external preprints (arXiv) via Valency. This is a separate corpus from the measurement records; results carry external IDs such as arXiv IDs or DOIs, not record_ids.

Returns: {available, results}; available=false when Valency is disabled or no token is configured.

Example: search_literature("high-entropy alloys", limit=5)

literature_trends

external

literature_trends(keyword, category=None)

Publication counts over time for a keyword, via Valency.

Returns: {available, keyword, trend}; available=false without a token.

Example: literature_trends("high-entropy alloy", category="cond-mat.mtrl-sci")

Environment

Variable Default Purpose
OMAT_OPENSEARCH_URL http://localhost:9200 OpenSearch endpoint the tools read.
OMAT_VALENCY_BEARER_TOKEN — Enables search_literature and literature_trends. Keep it server-side.
OMAT_VALENCY_ENABLED true Set to false to disable literature tools even with a token.
OMAT_VALENCY_MCP_URL https://mcp.valency.io/ Valency MCP endpoint.

Design notes

  • One OpenSearch document is one measurement property. Paper views group by DOI or PII; cite record_id for numeric claims.
  • The server is the only OpenSearch reader. Clients never get direct index access.
  • There is no application auth. Run the server on a trusted network, and keep it off public ingress until the ALB deployment exists.
  • Context is measurement records, not PDF chunks. There is no embedding or vector store in the search path.
